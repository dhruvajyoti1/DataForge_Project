Built for hands that are already busy

A technician mid-repair can't stop to type a search query or scroll a manual. EchoAssist is a voice-first assistant that stays on the line while you work, answers from the repair manual, and — critically — knows when to stop talking and listen if you interrupt it.

It's a working proof of the "interruption and recovery" problem: an assistant that removes speech as an input isn't just less convenient, it stops being usable at all for this job.

How it works

  1. 1
    Listen

    Deepgram transcribes what you say in real time, even with shop noise in the background.

  2. 2
    Respond

    The assistant answers immediately, grounded in the repair manual for the vehicle in front of you.

  3. 3
    Yield

    Start talking mid-answer and it stops, drops the stale answer, and listens to your new question instead.

EchoAssist is designed around real-time turn tracking and state fencing to handle clean voice interruptions:

  • Turn Tracking (TurnLog / SessionState): Every user prompt, tool call, and generated answer is tagged with a unique turn ID.
  • Task Fencing (is_stale()): Before returning a tool result or speaking an answer, the system checks if the user has spoken a new query. If a new turn has started, is_stale() evaluates to true and raises a CancelledError.
  • Single-Turn Speech Truncation: When a user speaks mid-response, the ongoing text-to-speech (TTS) stream stops immediately within one turn.
  • Stale Result Discarding: In-flight lookup tasks (such as database or manual queries) are canceled and discarded rather than queued or spoken later.
  • Single-Response Delivery: The final output reflects strictly the user's most recent request without blending, repeating, or combining content from the stale request.
  • Context Preservation without Stale Output: The system keeps the conversation history in memory so prior context isn't lost, but blocks any generated text or audio originating from the interrupted turn.
  • Interruption Logging: Event handlers track user_state_changed and conversation_item_added to log exact timestamps of interruptions and cutoffs for auditability.
